# Contributing to wikigpt

First, thank you for considering a contribution to this project. Open source relies on people like you to help it grow, whether you are fixing a small typo, updating documentation, or adding a major feature. 

By contributing to this project, you agree to respect our community guidelines and follow our [Code of Conduct](CODE_OF_CONDUCT.md).

---

## Getting Started

### Reporting a Bug
If you notice something broken, please check our existing open issues before creating a new one. It helps save time if someone else is already discussing or working on the same problem. 

If your issue is new, open a report and include:
* A brief summary of what went wrong.
* The steps required to reproduce the problem.
* The expected behavior versus what actually happened.
* Details about your local setup (like your operating system or language version).

If you discover a critical security vulnerability, please do not open a public issue. Instead, use the discussions page to report.

### Suggesting an Improvement
We welcome ideas for new features or changes to the codebase. When you suggest an enhancement, please describe the practical problem it solves. If you can provide a concrete example or a quick mockup of how you envision it working, that makes it much easier for maintainers to evaluate and discuss.

---

## The Workflow for Code and Documentation

We use a standard GitHub workflow for managing changes. If you are new to this process, here is the path your code will take:

1. **Fork the repository** to your personal GitHub account and clone it to your local machine.
2. **Create a new branch** specifically for your changes. Pick a short, descriptive name (for example, `fix/login-validation` or `docs/update-readme`).
3. **Make your edits** locally. Keep your commits small, focused, and accompanied by clear commit messages that explain *why* you made the change.
4. **Format and test your code.** Check that your changes do not break existing functionality and that they match the project's formatting conventions.
5. **Push your branch** to your fork, then open a Pull Request (PR) against our `main` branch.

Once your PR is open, a maintainer will review it. We may ask questions or suggest minor tweaks before merging it in. Don't worry if you need to make updates; that is a normal part of the review process.

---

## Coding Standards

To keep the project maintainable for everyone, we ask that you follow a few basic guidelines:
* Write clean, self-documenting code. Add comments to explain complex or non-obvious logic.
* Stick to the naming conventions already established in the codebase.
* If you are adding a new feature, include a corresponding test to prevent future breakages.

## Stuck or Have Questions?
If you have a question or get stuck while setting up the project, feel free to open a thread in our GitHub Discussions tab. We want to make sure you have the support you need to contribute successfully.
